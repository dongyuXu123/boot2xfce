## L04 —— 从"自己站 0x7C00"到"按协议供货"

MBR 时代我们自己抢位置；真实世界引导权属于 GRUB。Multiboot 1 协议就是一份
供货合同：内核在 ELF 前 8K 内、4 字节对齐处放一个头——

```
magic 0x1BADB002 | flags 0x3 | checksum = -(magic+flags)
```

GRUB 验签后把 ELF 的 LOAD 段搬到链接地址（我们链到 **1MiB**，避开实模式
地盘），跳到入口，并留下两样东西：`eax=0x2BADB002`（身份证）、
`ebx=信息结构地址（见面礼）`。cdecl 传参 = 先声明的参数后压栈，所以
`push ebx` 再 `push eax`，`kmain(magic, mb)` 正好接住。

**本课程实测最阴的坑**：GRUB2 的 multiboot1 加载器只认 flags 的
`0x1|0x2|0x10000`。想多要个内存映射把 bit6 也置上？`unsupported flag:
0x43` 直接拒载——而且报错只在 VGA 上，无头 QEMU 里表现为"串口一片死寂"。
想看它的遗言：`(sleep 5; echo "screendump /tmp/vga.ppm"; echo quit) |
qemu-system-i386 -cdrom build/boot.iso -display none -monitor stdio`。

链接脚本（kernel.ld）的职责：`. = 1M` 定位；四个输出节各 4K 对齐；
`.multiboot` 输入节必须排最前（头要在前 8K 内）；结尾导出 `kernel_end`——
L12 的物理内存管理要拿它当"内核占用到此为止"的界碑。

## L05 —— grub.cfg 与 ISO：引导的"配置面"

grub-mkrescue 产出 BIOS+EFI 混合 ISO（塞了全部 GRUB 模块所以十几 MB）。
grub.cfg 就三行的事：`timeout=0` 直接引导 + `menuentry` 里
`multiboot /boot/kernel.elf` + `boot`。注意路径是 **ISO 内路径**。
Makefile 侧：摆好 `build/iso/boot/{grub.cfg,kernel.elf}` → `grub-mkrescue`。

## L06/L07 —— 第一次接收硬件情报

信息结构 `flags` 是一张"有什么"清单：bit0=内存大小、bit6=E820 映射。
- `mem_lower/mem_upper`：常规内存(<1MiB)与扩展内存(KB)。打 MB 记得 /1024。
- **E820 是 OS 最贵的数据**：哪段地址可用/保留/ACPI 占用。两条大坑：
  ①记录真实长度在 `e->size` 字段且**不含自身**，步进 = `e->size + 4`，
  按 struct 大小走必炸；②遍历终点是 `mmap_addr + mmap_length`，不是数条数。

这张表就是 S2 物理内存管理（L12）的原材料——操作系统的一切，从"知道
哪块内存能用"开始。

# S2 讲义 · 内核四件套（L08-L19）

> 配套代码：`course/L08-console/` ~ `L19-capstone/`（均已实测通过）
> 深读：`docs/20-kernel.md`（Linux 源码对照表 + 全部实测坑位）

## 总图：一台机器的四个器官

```
内存管理(L12/L13)   进程管理(L14)      文件管理(L15)      API(L16/L17)
 物理页+内核堆   →   任务+调度器    ↔   ramfs 文件    ←→  int 0x80 + ring3
        ↑ 全部站在地基上：GDT/IDT/中断/时钟(L09-L11)，输出靠 console(L08)
```

## 地基层（L08-L11）

**L08 console**：双路输出 = 每个字符同时写 VGA 文本缓冲（0xB8000，一个字
16 位：低 8 位 ASCII 高 8 位属性）和串口。`print_dec` 从个位往回填缓冲——
除 10 取余天然是倒序。

**L09 GDT**：6 个描述符——内核码/数据（DPL0）、用户码/数据（DPL3）、TSS。
平坦模型下段基本是仪式，但 DPL 位是 ring3 的身份来源。TSS 是切换特权级时
CPU 找"内核栈在哪"的地方（esp0），L17 全靠它。自检用 `sgdt` 读 limit==47。

**L10 IDT**：256 个门 = 中断向量表。0-31 是 CPU 异常（除零/缺页…），
32-47 留给外设中断，0x80 是我们自留的系统调用门（DPL=3，用户可调）。
入口桩的使命：把所有中断整成**同一种栈帧**（struct regs），汇入一个 C
分发器。带错误码的异常要先 `pop` 掉 CPU 压的错误码存全局——不然 iret 时
栈型对不齐直接炸。

**L11 PIC+PIT**：8259A 把 IRQ0-15 重映射到向量 0x20-0x2F（不重映射 IRQ0
会撞 8 号异常门）。四步 ICW 初始化 + 屏蔽字只放行时钟/键盘。PIT 除数
1193182/100=100Hz 方波。从此 `ticks` 每秒自增 100——内核有了心跳。

## 内存管理（L12/L13）

**L12 PMM**：E820 → 位图，1 位=1 页 4KiB。分配=找第一个 0 位置 1，释放=清
位。三件事必须想清楚：
1. **保留区**：低 1MiB（BIOS/IVT）、内核镜像 [1M, kernel_end]、堆、用户区。
   ⚠️ 本仓库真 bug：最初没保留低 1MiB，alloc 从帧 0 扫起返回 0x0 页——
   被 L12 的功能断言（连续分配必须不同、释放后必须复用同页）揪出来的。
   **只打统计的测试不算测试，行为断言才算。**
2. **hint 优化**：记住上次分到哪，释放时把 hint 拉回去，分配近 O(1)。
3. mmap 遍历的 `e->size + 4` 步进坑（L07 已领教）。

**L13 堆**：物理页太粗（4KiB），任务栈/PCB 只要几百字节。12 字节块头
{size,used,next} 串成链表：首次适应找块 → 剩余够大就**分裂** → kfree 标
空闲并**向后合并**（合并后 size 变大，所以要用 while 继续看新邻居）。
验收断言的精髓：p2 释放后 kmalloc(150) 必须精确复用 p2 的地址——分裂
边界差 8 字节都过不了。

## 进程管理（L14）——全课程最重的一课

三个设计决定，每个都是一次架构选择：

1. **每任务一根 4KiB 内核栈**。中断现场天然压在"被打断任务"的栈上——
   这样切换时不用搬中断帧，谁被换出谁自己保管，恢复时各自完成 iret。
   （xv6 与现代 Linux 同款。）
2. **switch_to 只换 5 样东西**：esp + ebx/esi/edi/ebp。eax/ecx/edx 是
   caller-saved，C 编译器自己负责；EFLAGS 不存——**由此埋下 IF 不变量
   之坑（见下）**。`ret` 消费栈顶的 eip，等于"跳到新任务的断点"。
3. **蹦床制**。新任务的第一次被调度不能"恢复"（它没被保存过），所以
   在它自己的内核栈顶伪造一个 context：eip 指向蹦床。内核任务蹦床调
   entry；用户任务蹦床构造 iret 帧降级 ring3。

两个真 bug（都被课程断言揪出，详见 docs/20-kernel.md 坑位 6/7）：
- **初始 context 必须布在新任务自己的栈顶**。曾把 tasks[] 里的结构体当
  kesp 交给 switch_to——等于把 .bss 当栈用，蹦床的 push 把任务表踩穿。
- **IF 不变量**：switch_to 不存 EFLAGS，第一次切入任务时 IF 还是中断门
  清掉的 0，此后硬件中断全瞎（PIC 里 IRQ1 永远 pending，系统靠软中断
  空转）。修法：蹦床开头 `sti()`，此后 IF 由各任务的 iret 帧天然保存恢复。
  症状定位手段：HMP `info irq` 看 PIC 计数 + 内核里读 IRR/ISR。

调度器本体反而简单：`static last` 起环形扫 READY → 换状态 → 换 esp。
`task_yield` = `int $0x20` 软触发时钟门——**软件也能走硬件的路**，这是
理解"中断只是控制权转移机制"的钥匙。

## 文件管理（L15）

ramfs：固定 8 文件 × 512B，`write` 不存在就创建（名字逐字符拷留 \0）。
简陋但 create/read/write 语义是真的。S3 会换 vnode 抽象 + Ext2——
到时你会明白今天这 100 行是 VFS 的胚胎。

## API（L16/L17）——内核的用户界面

**L16**：`int 0x80`，eax=调用号 ebx/ecx/edx=参数。分发器就是个大 switch。
两个思考题的答案：
- exit 为什么不能 kfree 自己的栈？——你正站在那根栈上执行。
- write 的用户指针为什么敢直用？——无分页=同一地址空间。S3 开分页后
  这里必须换成"只翻一层"拷贝，否则用户传个内核指针就能读内核内存。

**L17 ring3**：用户程序单独编译（**-static -no-pie**！Ubuntu 默认 PIE 会让
平铺二进制膨胀成 4MB）成平铺二进制，`incbin` 嵌进内核，启动拷到 0x400000。
进入 ring3 的魔法是一次 `iretd`：依次压 用户ss(0x23)/esp/eflags(0x202)/
cs(0x1B)/eip，iret 一发降级。CPU 特权级从 0 变 3，从此用户代码的每个
越界动作都会被 CPU 拦下（真隔离要等分页，S3）。
用户态内联汇编必带 `"memory"` clobber：否则 GCC 把栈缓冲的存储重排到
int 之后，内核拷到的是旧内存——症状是打印的数字神秘消失。

## 毕业设计（L19）

新增 syscall 6 `writefile(name, buf, len)`：把用户缓冲写进 ramfs。要点
全在指针上：name 逐字符拷进内核（最多 15 字符留 \0）、buf memcpy 进
kbuf——**任何从用户态来的指针，进内核第一件事就是拷**。用户程序先
writefile 再 ls，串口断言同时盯返回值（ret=13）和文件表（cap.txt(13B)）。

## 毕业标准

从 int $0x80 到 iretd 回到 ring3，中间每一站你都能讲清楚：
门(DPL3) → 栈切换(esp0) → 桩保存现场 → C 分发器 → iretd 回 ring3。
讲得清，S3 见——分页、COW fork、ELF、Ext2、shell，每一个都会让今天
的四件套长出真肌肉。

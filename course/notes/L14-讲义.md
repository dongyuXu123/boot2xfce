# L14 · 任务与调度（全课程最重的一课） —— 讲义

**课程定位**：两个任务在同一颗 CPU 上同时跑——上下文切换的每根神经亲手接。本课骨架一直用到 S4 桌面。

**原理（对照真实实现）**：
- switch_to(old_slot,new_esp)：保存 ebx/esi/edi/ebp 四寄存器+esp 槽位，换栈后 ret 落入新任务 eip——纯软件上下文切换。
- 内核任务入口蹦床 ktask_trampoline：中断门把 IF 清了，蹦床第一句 sti 重建任务恒 IF=1 不变量（无此句首切后中断全瞎——L18 实测揪出）。
- 轮转调度：扫 READY 槽位，TSS esp0 为 ring3 中断备好内核栈。
- 协作让路 task_yield：int 0x20 软中断走同一调度路径。

**动手内容（对应任务书）**：
- switch_to 汇编 + 蹦床 + schedule 轮转 + task_yield——taskA/taskB 交替打印实测。

**验收**：make test：taskA/taskB 交替输出（调度实测）。

**坑与历史错误**（全部来自本项目实战，非虚构）：
- switch_to 不携带 EFLAGS：被切入者继承切出者的 IF。协作切换都发生在 int80 门内（IF=0），关中断态会沿调度链传染——S4 实测被切入的内核任务以 IF=0 跑满时间片（时钟/键鼠停一拍）。课程版靠 PIT 抢占用户态+用户 iretd 自愈共存；根治需 per-task EFLAGS 恢复（S4 尝试三版：ISR 内恢复行=确定性 GP 0xba0c@iretd，已证伪；细节见项目 README）。
- esp 占位：pusha 的栈映像里 esp 槽必须跳过不恢复（硬件在中断时已修正）。
- 先切栈再切 CR3 顺序错 = 换完页表还在旧栈上执行——S3 分页课后任务切换才完整。
- S4 加课建议：exit 系统调用必须 schedule 切走（死任务霸占 CPU 会随机腐蚀，见 S4 syscall.c）。

# L16 · int 0x80 系统调用 —— 讲义

**课程定位**：定义你这台机器的 ABI——用户程序与内核的唯一合法通道。

**原理（对照真实实现）**：
- 约定：eax=调用号、ebx/ecx/edx=参数、返回值写回 eax；分发器 switch 路由。
- 五调用起步：write(1)/read(2)/exit(3)/uptime(4)/ls(5)。
- 所有用户指针必须 uptr_ok 校验后经内核缓冲拷贝——用户数据不可信。

**动手内容（对应任务书）**：
- syscall.c 五个 case + 用户态 sys() 内联汇编。

**验收**：make test：用户程序经 int 0x80 打印，内核态实测。

**坑与历史错误**（全部来自本项目实战，非虚构）：
- 用户指针必须校验（uptr_ok）并拷入内核缓冲——直接解引用用户指针等于把内核暴露给任意写入。
- int 0x80 是中断门：进入即 IF=0，阻塞系统调用里 schedule 让路后，iretd 会自然恢复用户 IF=1——别在处理函数里手动 sti（S4 实测：嵌套恢复破坏 iret 帧，GP 0xba0c）。
- exit(3) 必须立即切走且永不返回：死任务霸占 CPU 时，S3 引入的 kfree 会收走其内核栈而 TSS esp0 仍指着它，每个中断都往已释放的栈压帧随机腐蚀（S4 GP 0xba0c 实测）。S2 阶段靠用户桩 .hang 侥幸，务必写对：schedule() 切走 + for(;;)hlt()。
